# JD v6：自进化任务处理修复

针对官方接口文档与当前任务实现的核对结果，修复“正确解题程序被拒绝”和“已返回答案在避险分支中未处理”的确定性失败路径。开发分支 zk_dev，基于 JD v5；任务以外的采矿、建墙、投资和炮火策略沿用 v5。

## 行为变化

- 任务入口给出 Markdown 文件时，先读取当前文件。模型提示、skill 的题型匹配和 solve(task) 输入统一包含入口描述和读取到的正文；缓存查找也在读题之后进行。保留裁判返回的正文，不再自行截掉其中一段；裁判的 64KB 输出限制仍然存在。
- 优先直接提交已有证据支持的答案，不要求为了缓存解法再生成程序。skill 仍在裁判沙盒执行；开发机不会运行实际模型生成的代码。
- 每回合先接收并保存模型/沙盒返回，再决定是否继续工作。普通路径避险区内，有现成答案且机器人尚未逼近时优先提交；机器人距离不超过 max(2, 攻击范围+1) 时先用药或撤退。用药暂停期间保留答案或待执行命令；任务结束后清除，避免串题。撤离任务点仍会结束任务，不能保证每次都可提交。
- 默认取消任务内固定 12 次模型调用和 16 次命令上限，受任务剩余回合约束。领取指令发出时记录起点；进入临界时间后禁止无法及时处理结果的命令，提示模型直接提交。耗尽期限仍会离开任务点。
- 分别反馈 JSON 结构错误、skill 代码/题型匹配错误、命令错误、网络故障和裁判答题反馈。较长说明文字之后的协议 JSON 也能被识别；仍要求 action/answer 等约定字段，不将任意日志对象当成答案。
- 仅在提交后下一回合任务消失、无错误、动作合法、领取时间已知且尚未到期限、开拓者存活且位置未变时保存解法。这是依据任务结束规则排除其他原因的保守确认，接口没有独立的“答案正确”布尔字段。忽略旧 v5 缓存，避免继承未经充分确认的解法。
- 任务诊断仍写入 ZK_STATE_DIR 下的 *_trace.jsonl，包含原始返回、错误和待处理阶段；遇险回合也会记录。

## 验证和边界

详见 [自动冒烟记录](../production/qa/smoke-v6-2026-09-18.md)。新增测试运行固定、审阅过的解题程序，验证其从完整正文计算并提交答案，再换题重新计算。模型返回与裁判反馈由测试夹具提供，不把通过测试等同于真实模型解题率。

本版消除已复现的程序阻断，不承诺所有题必然成功。真实题目的求解能力、外部模型/沙盒故障、任务期限和人物遇险仍会影响结果。没有真实裁判服务的端到端实战成绩可供本次验证。
