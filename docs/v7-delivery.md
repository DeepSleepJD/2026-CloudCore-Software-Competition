# JD v7：任务流程与质量检查

在 v6 上独立实现第一批优化：题型流程、查询完整性、答案校验、防止重复失败。参考项目仅用于分析设计思路，没有复制其源文件、固定答案、服务地址或认证值。

## 运行方式

- 读取题目正文后分为查询统计、工程修复、未知题。分类只用于选择工作流程，特殊问题仍可使用原 command/skill/answer 协议。
- 新增 query 动作：模型依据本题文档提供 GET 地址、认证头、查询参数、数据字段路径和分页方式。工具支持 offset/page/cursor，必须提供总量或结束证据；明确不分页的接口才允许无分页模式。地址必须出现在本题或实际文档输出中。
- 查询在裁判沙盒中一次完成多页获取，核对业务状态、记录数组、总量变化、重复页和结束标记；可按本题 ID 字段去重，offset 按原始页长推进。确认的空数据集可以提交，鉴权失败、漏页、总量矛盾不会作为完整结果。
- 聚合支持 count、distinct、sum、min、max、first_by、last_by、精确字段过滤。年代字符串需要显式顺序，不能用字符串排序猜年代。成功返回的答案直接进入提交检查，省去额外模型往返。
- 从明确标注的提交格式段落读取有效 JSON 示例，检查额外字段、对象/数组/数字/字符串类型。允许提交已求得的字段子集争取部分分；不从 API 响应示例推断答案格式，不对含占位符的非法 JSON 示例猜类型。
- 工程题仅在正文明确给出唯一可识别验收命令、至多一个工作目录、TOKEN 输出及 token 答案格式时，自动执行独立验收。非零退出、明确失败行、缺少或出现多个不同 token 均不提交。修复 command 可带 verify=true，成功后自动验收；模型猜出的 token 会被实际验收结果替换。
- 相同操作连续两次返回相同结果时阻止第三次重复；结果变化、命令修正或中间发生新操作仍可继续。裁判 errorCode=2 的答案按规范化 JSON 记录，调整键顺序或空格不能绕过禁止重交。
- 自建查询/验收工具使用请求标识关联结果，旧请求返回不会用于当前任务。工具运行限制约 10 秒查询、8 秒验收；查询最多 24 页、10000 条记录，每个 HTTP 响应最多 1MiB；达到限制则报告未完成而非输出伪成功。

## 边界

这些检查不能证明模型选择的统计口径一定正确。自建 query 工具执行完整性检查；任意 command/skill 仍由模型编写，我们只能识别部分明确错误和分页不完整输出，不能静态证明任意程序已经查全所有数据。非 GET、特殊认证、非对象记录数组、特殊验收命令或非 TOKEN 输出需要通用流程。

自动验收识别存在明确边界，不自动猜测多个目录或命令。未知题不会因为缺少预设题型而被拒绝。真实裁判、真实题库和线上模型未在本机联调；自动测试通过不等同于实际任务全对或夺冠。

任务收益调度、采矿完整往返收益和多炮协作不在本批范围。提交格式仍为 CoreGeek 根目录的 tar.gz，main3.py/run.sh 入口、Python 3.10+、仅标准库；健康检查版本 v7-jd。
