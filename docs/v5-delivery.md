# JD v5 交付说明

在 zk_dev 的 v4 基础上，针对三份对手回放和已复现缺陷改进；回放中的“对了对了不队”是衍生版本，不能视为当前程序。详细复盘见 ../analysis/三份对战记录策略分析.md。

## 本次行为

- 任务描述明确给出 Markdown 文件名时，先通过裁判沙盒读取文件，再交给比赛模型。长期保留题目文件内容，提示模型区分数据统计和交互取 token 的题型，并传入剩余回合；没有硬编码回放答案。模型直接答题成功不等于形成可复用解法，缓存仍要求返回并验证 skill。
- 任务期间人物受威胁会用药或撤退，不为做题站在怪群附近。模型、沙盒和错误反馈写入本地有大小上限的任务诊断记录，位于 ZK_STATE_DIR（默认 .zk_state）下的 *_trace.jsonl；这些文件不进入提交包。
- 修复工人拿维修包在 600 血墙旁反复移动的问题。近身使用、采购和普通维修统一以墙体 80% 血量作为维护门槛；送到后实际使用。紧急基地升级在近身行动中优先处理。
- 投资购买记录目标建筑，携券人员优先向指定建筑交付；解除无用目标时可处理其他可用物资。多个角色仍共享预算并避免重复购买。
- 三座火箭建成后，一个工人主要补墙，另一个保留采矿收入。保留矿点与出售阶段，对连续两格往返触发重新安排；工人低于 160 血且资金允许时提前购药。
- 夜间不统一撤离：正常路线避开机器人危险区，活跃波次中的采矿只选择安全路径上八步以内的矿点；低血量人员回安全区。临近天黑、远离防线的人会提前回撤，避免站在刷新区等怪出现。
- 己方波次清空后允许夜间任务；若仍有己方威胁，必须有工人到炮位接班才允许开拓者外出。附近的对方机器人同样计入路径危险，不把“己方波次清空”等同于全图安全。
- 移除原有固定火炮升级队列。采购比较当前防守需求、各座炮及基地的估计收益，除以物资价格与配送距离成本；基地或墙即将倒塌时优先救急。仍保留建炮和关键维护预算，属于轻量启发式，不是精确最优求解。

## 测试与限制

新增回归覆盖连续送修到使用、基地旁有券立即救急、两个任务类别的文件读取与模型答题链路、无效模型回复、夜间远处有怪仍可做安全任务、夜间安全采矿、天黑前回撤、经济工人不被补墙占满、目标建筑绑定和接炮交接。

真实裁判沙盒题目和模型服务不在本地，本次任务测试使用可控模型与命令结果。不能据此承诺真实解题率或胜率；诊断记录用于实战失败时定位具体阶段。

官方提交包为 artifacts/CoreGeek.tar.gz，根目录 CoreGeek，入口 main3.py 或 run.sh，健康检查版本 v5-jd。Python 3.10+，无需第三方运行依赖。
