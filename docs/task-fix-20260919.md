# 自进化任务修复与验证

## 修改

- build_info.py：启动时生成源码内容指纹，server 输出 agent_build，任务 trace 携带 buildId；上传完整目录后可比对实际部署版本。
- task_prompt.py：提示词从调度器提取，统一四种操作和准确调用契约；明确只把实际输出作为答案来源，不接受模型自报 evidence。
- tasks.py：prompt 携带实际 httpHelper；task_result 模型回复仅兼容读取 answer，忽略所有模型证据。最终答案必须与当前沙盒验证结果完全一致，JSON 布尔值不能冒充数字。
- task_sop.py：从成功响应学习 endpoint/cityParam/authHeader/recordsPath/paginationPath，保存无凭据、无答案的 SOP。每次重新查询全部 offset/limit 页，拒绝重复页、重复ID、总数改变、空页、缺页及错误响应。保护级别统计使用实际 protected_level 字段。
- 验证时重新从各页数据计算条数、类型集合、世界遗产数量和最早记录名称；模型声明的条数和完整标记不参与校验。
- 当前城市与任务标题/查询描述核对，文档中顺带提到上一题城市不能作为执行旧城市的依据。
- 结构化 SOP 结果通过校验后同回合 submitAnswer；普通脚本仍保留处理反馈所需预算。token直接提交要求检查器输出与token一致。
- bootstrap 将辅助HTTP程序和SOP一并送入沙盒，通过压缩命令保持在16000字符限制以内。SOP调用包含12秒进程闹钟（平台支持时），HTTP共享10秒预算，最多30页，结构化输出最多56000字节。

## 测试

执行：`python -X utf8 -B -m unittest discover`

最终结果：79项测试全部通过（2026-09-19）。本次源码 buildId：`1b4baf284398d66c`。
后续修改源码会改变该值，应重新运行 `python -X utf8 -B -m agent.build_info` 获取上传版本的指纹。

新增回归覆盖：提示词实际路径、普通文本中的业务失败、模型覆盖分页计数、模型修改token、检查器直接提交、失败后清除旧答案。

真实本地HTTP服务提供模拟题数据：北京15条、南京12条，默认每页10条；API文档采用过时认证方式，查询参数错误可获得真实400响应。
连续任务测试通过以下流程：

| 阶段 | 时限 | 提交耗时（接取到提交） | 行为 |
|---|---:|---:|---|
| 首题 | 15回合 | 8回合 | bootstrap、错误city探测及认证修正、location探测、固定SOP取全两页并直提 |
| 同类后续题 | 10回合 | 4回合 | bootstrap、复用SOP重新查询当前城市两页并直提 |

另测缺页、重复页、重复ID、业务错误、错误城市、伪造统计值，以及仅剩3回合时SOP仍可提交并收到反馈。
测试只从真正发送给模型的prompt读取辅助路径，避免使用内部状态替代模型可见上下文。

调整了旧测试中两种不可靠假设：模型可以直接改写token，以及只输出统计JSON就足以证明完整分页。现要求前者重新取得沙盒证据，后者提供固定SOP读取的原始页数据。

## 边界

这些是本地HTTP/沙盒进程与合成平台反馈测试，没有调用官方平台或真实比赛LLM，不等于已在官方比赛完成任务。
SOP仅在观察到受支持的records/pagination及字段结构后启用，后续调用再次校验结构；不硬编码回放答案。
年代排序使用显式年代词表；遇到未识别年代或多个记录处于同一最早档位时拒绝自动提交，不猜测先后。
对于未知API结构，保留沙盒探索反馈，但不会把无原始数据证明的统计JSON当成正确结果提交。
运行中的旧进程不会自动加载本次代码；请以重启后的agent_build日志核对版本。
