# 首版生存策略开发依据

## 已阅读的本地材料

- `../../Competition-main/docs/任务书.md`：地图、动作权限、费用、距离、昼夜、结算顺序及异常规则。
- `../../Competition-main/docs/接口文档.md`：HTTP 启动、Request/Response 字段、角色类型、ID 与动作结构。
- `../../Competition-main/docs/request.txt`、`response.txt`：请求及动作变体示例。
- `../../Competition-main/Demo/CoreGeek/`：`main3.py` 和 `server.py` 的 HTTP 生命周期、`protocol.py` 的坐标和字段解析、`grid.py` 的八方向寻路、`brain.py` 的建造圈层。
- `../../replay.json`：队伍 `Agentic麻辣烫`，teamId `4284`，在本回放为 defender。

程序采用 Demo 相同的“启动 HTTP Server → 接收状态 → 返回本回合动作”方式，未修改官方 Demo。
官方 Demo 按三个角色分别分配三种炮台，本实现改为一个角色轮流操控三台火箭台。

## 接口约束

| 项目 | 当前实现 |
| --- | --- |
| 监听 | `0.0.0.0`，命令行传入端口 |
| 返回 | HTTP 200、UTF-8 JSON、Content-Type 与 Content-Length |
| 顶层字段 | `roleCommandMap` 对象、`prompt` 字符串、`executeCmd` 字符串 |
| JSON key | 角色/武器 ID 转成字符串；不依赖固定 ID |
| 坐标 | `targetPos` 必须是 `[{"x":整数,"y":整数}]` 形式的数组 |
| 攻击 | 命令属于武器 ID；`controllerId` 为角色 ID 字符串 |
| 操作互斥 | 控制武器的角色不再提交移动、采集等指令；同回合只操作一座 |
| 权限 | 仅工人采矿；仅白天工人建造；仅夜晚武器攻击 |
| 冷却与目标数 | 只用 cooldown=0 的火箭台，目标数组长度等于等级 |
| 费用与容量 | 本回合共享金币预算；预留重建费用；检查背包容量 |
| 无动作 | 不提交该 ID，不发文档未定义的 `nothing` 动作 |

`response.txt` 是动作目录，存在重复 key，且 summonTreasure 片段缺少逗号；不能当作一份可直接解析、原样返回的 JSON 模板。
回放使用数值 roleType、`backpacks`、`commands.targetName`，它们也不是实时接口字段。

坐标原点是左下角，基地 `pos` 是左上角。基地占 `(x,y)`、`(x+1,y)`、`(x,y-1)`、`(x+1,y-1)`。
距离用切比雪夫距离；可对角移动；不额外添加“禁止夹角穿越”限制。
武器在基地占地外一圈，围墙在外两圈，此点结合 Demo 几何与回放中成功建造的位置确定。

## 本次实现的布局与取舍

defender 示例基地 `(30,10)`：三台火箭台 `(32,9)`、`(31,11)`、`(32,11)`，操作格 `(32,10)`。
围墙为 x=28、y=7..12 的前沿，以及 y=7/12、x=29..31 的上下侧，总计 12 段。
左上基地以 2×2 基地中心旋转 180° 得到镜像，因此迎敌侧在右，火箭台在左。
背面保持开放以便采集和运送；用实际基地坐标判断方向，换边不绑定队伍名字。

与冠军不同，本版不获取任务收益：首日三台火箭台预算能由初始金币保证，但主炮首日升级不能保证。
矿点距离、枯竭刷新与双方碰撞也会影响建墙时间。优先把最前沿墙建起来，再封上下侧。
资源收益只使用服务器提供的 vendorShopList；没有解析新闻预测未来价格，也不会假设采矿禁令结束时间。
失败采集会暂停尝试该矿点 10 回合，再依据新状态重试。

火箭命中评分使用机器人移动前的位置、20 中心伤害和 10 溅射伤害；倾向保卫己方基地、集群和可击杀目标。
多发落点按预测剩余血量递减，允许重叠，但不是全局最优弹药分配。
等级、范围、冷却、金币、血量均每回合从服务器重新读取，优先于本地历史推测。

## 待真实平台验证

当前工作区没有比赛服务端、调测入口或运行环境说明，无法在真实机器人移动和伤害结算下验证存活天数。
接口也没有直接提供可建造区域掩码，目前使用文档示意、官方 Demo 与回放一致的建造圈层。
后续应先用 `bash run.sh <port>` 接入平台，检查错误列表、动作合法性反馈、首夜基地血量、
两侧首日建造进度和后续维修收入，再调整经济与墙体维护阈值。
本版尚未预测敌方角色/机器人本回合移动，因此可能出现规则允许但执行失败的碰撞。
任务策略和冠军任务收益复现保留给下一阶段。
