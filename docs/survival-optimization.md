# 第二轮生存优化

基线：`a7b2b00`；保持平台入口 `main3.py`，保持 HTTP 和动作协议。本轮不新增做任务能力。

## 证据与边界

用户报告：`D:\2026-云核软件大赛\Competition-main\Competition-main\对战记录\生存天数对比记录.md`。
当前目录只有报告，没有其引用的 battle1.json / battle2.json，因此不能重放这两场比赛或证明所有失守因果。
报告的金币积累、基地等级和生存差异提供了定位方向，但“完全由防御质量决定”“满级基本稳过某夜”等属于推断。

报告中围墙 L2/L3 的 2000/3000 血与当前任务书的 1500/2000 不同；部分武器数量之和为 4，也与最多 3 座不符。
实现继续遵守本地任务书。基地血量 1500→3000→4500，第二次升级不是再次翻倍。

- 第 679 回合附近，两名工人储备大量修复包；第 720 回合背包分别有 9 和 10 个。
- 第 737、744、752、759、767、776 等回合，工人在 `(29,9)` 反复修复 `(28,9)` 的前沿墙。
- 后期基地维持 L2、武器维持 2/2/3，基地在第 650～980 回合的多个快照仍有 2680 血；持续维修是不能忽视的一环。
- 本局第 1024 回合结束获胜，没有打满 1300 回合。不能把胜利等同于证明能独立抵挡所有十夜浪潮。

## 代码中找到并修复的问题

1. **基地投资过晚。** 原策略通常要等三台火箭台全部满级才升基地，只有基地血量掉到阈值以下才插队。现在将基地升级加入天数优先级：L1 在第 3 天必须成为下一战略目标；第 2 天主炮已 L2 时也优先升基地。L2 在第 4 天优先升 L3，若第 3 天主炮已 L3 则提前。低血量进一步提前。资金、商品或通路不足仍可能延迟，不能保证某天必定完成。
2. **运送依赖开拓者。** 战略券选择可达且合适的角色运送，并保持当前运送人，避免每回合换人。夜间炮手不参与购物，工人可以运送基地/武器券。券已经在活着的角色背包时不再重复购买；实际使用始终以新请求确认的等级为准。
3. **往返途中预算被花掉。** 当前战略购置预留预算；当两次基地升级已连续到期时，额外保留二级券资金，避免第一个券还没送到，后一个券的钱已被零散补货花掉。每回合仍用服务器金币重算，不假定卖矿和购买在同回合能互相融资。
4. **夜间维修被避险覆盖。** 原代码先判断机器人周围 4 格为危险并撤退，导致 `(29,9)` 这种冠军常用维修位无法执行修墙。现在优先使用有效补给，健康维修工可在基地内侧一圈、与机器人至少相距 3 格的邻墙格操作；机器人更近或血量不足 80 时不授予这个风险例外。此规则不假设围墙能挡住远程伤害，仍需平台观察维修工生存情况。
5. **逐个购买修复包。** 第 2 天储备目标为 2 个，第 3～4 天为 4 个，第 5 天起为 6 个，按资金/容量截断批量购买；独立角色可分别买药。夜间维修岗保留在基地内侧，另一工人继续采矿。损伤突增时结合近期血量变化提高维修触发阈值。
6. **基地入口拥堵。** 长途可行性估计允许考虑队友稍后让路，实际一步移动仍完整避让。闲置工人会让出后方窄入口，避免“有钱、有人、有券，但基地无法接近”的停滞。
7. **小批矿不能及时兑现。** 当少量矿石已足以补足下一战略升级券差额时提前出售，而不是一律凑 12 个再去交易。
8. **返岗估计偏乐观。** 开拓者的返岗和采购后回程时间使用八方向寻路估计，包含已建墙体阻挡，保留时间余量。

优先级主要集中在 `agent/logistics.py`；调度与动作互斥在 `agent/strategy.py`；
`agent/navigation.py` 的 `ignore_actors` 仅用于长途估计，不用于真实下一步移动。
策略记忆仍为本局内存状态，在换队、换边、回合回退时清空。

## 代价与下一步观察

维修工驻守会减少采矿时间；优先升级基地也会推迟第二、第三台火箭台满级。这是本轮有意采取的生存取舍，
不能单凭支出增加就宣称胜率上升。当前经济模拟中的机器人一直存活、没有伤害结算，因此会让维修岗持续占用，
不适合据此估算真实收入下降比例。真实对战应重点记录基地升级回合、金币与背包券滞留、
首个墙洞回合、修复包使用次数、维修工死亡和枪炮空闲回合。

未来任务收益会改变建设预算。任务开发应接入统一角色分配，避免夜间撤走炮手或采购消耗防御储备。
可直接使用 `docs/task-development-prompt.md`；该文档包含完整材料路径和冠军接取/提交任务的回合线索。

```powershell
python -B tools/compare_survival.py --baseline a7b2b00 --rounds 1300 --output docs/survival-comparison.json
python -B tools/analyze_replay.py ../replay.json --validate
```

对照工具从 Git 读取基线模块，不切换分支、不覆盖工作区。它包括无新增收入的 276 金币场景、
固定每回合 80 点墙伤的维修场景，以及左右两侧资源/升级推演。完整结果写入 `survival-comparison.json`。
这些是受控回归与资源闭环验证，不是官方对战模拟，不能输出真实存活天数。
