# JD v4 交付说明

本版从 `feature/jd` 的 `a7b2b00` 引入运行代码，在 `zk_dev` 上增加任务、敌我识别和防守调度。保留 JD 的三火箭、十二段正面墙布局；没有改动 `feature/jd`。

## 行为变化

| 回放问题 | 本版处理 | 边界 |
| --- | --- | --- |
| 炮击另一队的机器人 | 优先看 targetTeam；无标记时结合位置和连续移动判断 | 敌方机器人贴近基地或刚受伤人物时允许自保 |
| 三种任务没有执行 | 自进化任务接入比赛模型与沙盒；官方新闻影响采售；民间新闻生成宝藏计划 | 模型回复需要通过结构、日期、材料和新闻原文校验，仍不能保证推理正确 |
| 墙体维护被武器升级挤占 | 根据受压、掉血和剩余夜长预留防守预算；持续受压考虑升级，临近天亮偏向维修 | 无威胁时不一律升级所有墙 |
| 开拓者白天闲置 | 有回程时间时接任务、准备宝藏或执行后勤 | 夜间炮位先安排接班；允许必要的安全等待 |
| 人物撤退导致维修送不到 | 先做近身救急，短途送修按预计伤害判断能否完成 | 人物无法承受时仍撤退 |

采矿目标和出售流程跨回合保留，避免反复改道。同回合和在途采购去重，所有人员共享金币预算。囤矿必须留够防守资金；缺钱或背包满时出售。任务中的开拓者由工人接炮，夜间接班工人持续守到天亮，避免交接空档。

宝藏只有地点、日期、昼夜、材料和新闻证据齐备才行动。成功或已被挖空即停止；材料错误作废计划，最多尝试两次，避免持续消耗金币。新闻解析在任务外每天最多三次，任务本身有调用和沙盒命令预算。

模型请求通过比赛提供的协议交给裁判端执行，不调用本机 Claude，也不需要把个人 API 密钥放进提交包。自动测试使用预设模型回复，所以真实模型的解题率和新闻理解率仍是未验证项。

## 提交与启动

上传仓库 `artifacts/CoreGeek.tar.gz` 的文件本体。不要上传 GitHub 自动生成的仓库源码压缩包。解压目录是 `CoreGeek/`，入口保持为 `CoreGeek/main3.py`，监听平台传入的端口：

```bash
python3 main3.py 8080
# 或
bash run.sh 8080
```

需要 Python 3.10+，运行时仅用标准库。健康检查返回版本 `v4-jd`、请求数、最近回合、动作数和异常类型。`BUILD.json` 记录源代码提交；重复回合返回原决策，避免重复消耗调用额度。

提交包只包含新运行入口及 `agent/`；旧 `zk_agent/` 留在仓库做回归对照，不会被平台运行。包内不含回放、个人凭据或本地任务缓存。

## 测试方法与结果边界

见 [冒烟记录](../production/qa/smoke-2026-09-18.md)。用少量高风险场景、自动边界组合和连续回合覆盖行为；再故意破坏四项关键逻辑，验证测试确实能够检出问题。部署测试直接解压提交包，从其他工作目录启动真实 HTTP 服务，并发送平台形状的请求。

小模拟没有完整机器人 AI、对手策略、官方建造区域和最终计分器。回放测试仅检查历史快照上的动作，无法计算新策略的胜率。当前结果可以证明已覆盖场景与部署链路通过，不能证明夺冠或官方整局无故障。
