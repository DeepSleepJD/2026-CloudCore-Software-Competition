# zk_agent v2：半围墙、主动工作调度与火箭轮换

本分支在原始任务书、接口文档和 Demo 之外增加一套独立参赛程序。Python 3.11+，仅使用标准库，无须安装依赖。原始文档和 Demo 保持原样。

## 启动

Linux 比赛入口：

```bash
bash run.sh 8080
```

指定配置：

```bash
bash run.sh 8080 --config config.example.json
```

Windows 本地调试：

```powershell
python -m zk_agent 8080 --config config.example.json
```

服务监听 `0.0.0.0`，接受任意路径的 HTTP POST JSON；GET 返回健康检查信息。判题请求返回 `roleCommandMap`、`prompt` 和 `executeCmd`。同一回合重复请求返回同一份决策，避免重复消耗任务状态。每半场独立启动服务；回合数回退或阵营变化也会清理战局状态。

## 本版策略

### 1. 固定防守和经济

- 初始建两座炮：火箭、加特林，共50金币，预留25金币。不是同时安排三个人永久守家。
- 按已知“中央出怪、双方在左上和右下”的条件，左上修右侧/下侧，右下修左侧/上侧。默认6段关键墙，从迎敌拐角向两侧交替补齐，背面保持通行；不会为了去商店把正面开一个大口子。
- 两名工人建设、采矿、批量卖矿；第一名工人优先补尚未建成且可尝试的关键墙。墙完成后转经济，不继续按全场墙数盲目采石。石矿不可用时改采可达的其他矿石。
- 读取实际矿价，按固定批量收益与路程估算选择矿点。卖矿目的地不可达时继续尝试其他工作，购买升级券优先交给可达且空闲的近处角色，避免两人同时长途跑商店。
- 同一回合共用金币预算、预留移动目标，出售所得不提前计入本回合预算。
- 按当前可通行路径长度加6回合余量返程。找不到回炮台的路不会导致白天永久等待；会尝试其他工作或恢复通路。建墙前检查是否会切断现有商店和操炮路线。
- 默认两座火箭的预设位置有共同操炮站位，一个工人根据冷却交替发射，另一个工人操作加特林。任务中的开拓者不被普通操炮调度打断。布局不满足共同站位时退回独立分配，有空闲开拓者时可接管第三座炮。
- 炮台冷却或无目标时，尝试原地采集、出售、购买、使用升级券、修复包或召唤令；不为了采矿错过下一次开火。没有合法有益动作才守位，并记录原因，不用空打或来回移动伪装忙碌。
- 优先集中升级主力火箭到三级；基地低于70%血量时优先购买可用的基地升级券。已携带的基地升级券在夜间也能用于紧急恢复。
- 上一日基地掉血时优先补第三炮；正常扩建需要至少50金币，且进入第二天或已有二级炮，花25金币后保留25金币。`third_tower_reserve` 可以修改这笔预留。
- 基地低血且附近有机器人，或工人不足两人且机器人逼近时，开拓者紧急回防。低血角色在没有开火机会时尝试避开机器人。
- 已有药品、修墙包、炸弹、眩晕道具会按受伤和机器人聚集情况使用；有需要且预算允许时购买药品或修墙包。不会为了“用掉资源”无条件浪费道具。
- 火箭选择可获得较高有效溅射伤害的位置，按已计划伤害减少重复攻击；加特林同方向发射，满足90度夹角要求。电磁炮使用简单目标选择，不假设判题器的精确栅格穿透算法。

### 工作接续和停滞处理

- 每个没有动作的角色都会经过备用工作检查：保命、返程、配送升级券、购物、经济、清理堵路围墙、侦察或去即将刷新的任务点。
- 移动、交易等动作收到失败反馈后暂时避开相同指令。连续数回合位置不变且仍试图移动时，暂时避开当前下一步；`idle_replan_rounds` 默认3。
- 只有拆掉某一面己方墙能恢复原本不可达的有用路线，才考虑拆墙；不会为了活动而乱拆前线。夜间附近有机器人时不拆该墙。拆开的格子暂时不重建。
- 任务等待结果、任务点冷却、守炮无目标/冷却、路线受阻等分别写入标准错误日志，包含回合和角色ID。日志中的 `waiting=` 是原因，`rounds=` 是连续计数。
- 无任务的开拓者可以运送自己背包里的升级券、交易、购买补给；角色之间没有凭空转移物品的操作。

### 2. 任务解法复用

开拓者前往己方有效任务点，接取后驻留。第一次收到任务，通过比赛提供的 `prompt` 和 `executeCmd` 逐回合探索，不在HTTP请求中直接调用外部模型服务。

模型只需返回三种结构之一：

```json
{"action":"command","command":"沙盒命令"}
```

```json
{"action":"answer","answer":{"题目要求的字段":"答案"}}
```

```json
{"action":"skill","match":["区分该题型的稳定子串"],"python":"def solve(task):\n    # 解析本次任务参数并求解\n    return ..."}
```

- 生成的代码只发送到比赛沙盒执行，不在选手HTTP服务进程中执行。
- `solve(task)`接收当前任务全文，返回答案。命令执行成功并输出约定标记后，程序提交答案。
- 答案提交后，必须看到任务结束、角色上回合动作成功、没有答案错误或超时，才将候选解法加入缓存。无法确认时不缓存。
- 相同题型使用稳定子串匹配，复用求解过程、重新计算参数，不缓存跨任务的固定答案。匹配不是语义证明，任务变化较大时仍可能失败并重新探索。
- 缓存命中后，典型流程是：接取 `t` → `t+1` 执行缓存解法 → `t+2` 提交答案。没有宣称所有任务都能1回合完成。
- 单任务默认最多12次模型调用、16次沙盒命令，避免坏回复无限重试；这是程序自己的预算，可以配置。只在有活动任务时发起这些调用，不消耗常规每日3次额度。模型预算耗尽且没有答案可提交时离开任务点结束任务，避免一直站到超时；可能放弃尚未完成的题目，因此复杂题可调高预算。
- 模型、命令和答案都可能失败；失败后将近期结果反馈给模型。没有把题目内容、文件位置或答案硬编码成虚构数据。

缓存保存在 `.zk_state/`，按队伍和阵营区分，不提交到Git。需要完全清空历史解法时，可切换到一个新的 `state_dir`。本版尚未实现新闻推理和寻宝。

### 3. 全图火箭试射

`pvp_mode` 有三个值：

| 模式 | 行为 |
|---|---|
| `off` | 只打机器人 |
| `auto`（默认） | 满足防守条件后试射基地，再根据下一回合反馈决定是否继续 |
| `on` | 显式实验模式，跳过试射确认，仍保留优先防守条件 |

试射要求：三级火箭、敌基地可见且在射程内、己方基地至少70%血量、己方基地8格内及工人4格内没有面向己方的机器人。未知能力时每回合最多一座炮试射。

- 三枚导弹落点相同，利用文档明确写出的重叠伤害。
- 试射被判为执行失败，停止自动PvP；两次可归因的合法试射都没有造成伤害，也停止。
- 只有连续下一回合、敌基地未升级、试射前敌基地附近无机器人等条件成立时，掉血才记为支持PvP的经验性证据。存在其他未公开机制时仍可能误判，日志不会把它当成数学证明。
- 确认后，优先打可见的低血量敌方角色，其次打基地；不会凭空推测视野外角色位置。基地可受伤不代表角色必然可受伤，这部分仍是待验证的战术。
- 日志记录 `observed damage` 和单次正常叠射预期值60，便于人工检查2×2基地是否重复承受溅射。不会预先按重复伤害计算胜率。

一座三级火箭总成本275金币。本版不会把“全图”当成开局能力，也不会用初始75金币虚构满级配置。

### 4. 有条件偷袭

`enable_raids` 默认开启：

- 全图火箭已得到可攻击基地的试射证据（或显式开启PvP实验模式）、基地安全、开拓者健康且没有当前任务时，可以在任务空档接近敌方基地提供视野，供火箭攻击可见炮手。
- 侦察避开当前可见机器人的近距离区域和敌方炮台射程，不假定视野外安全；已知任务很快刷新时不跑远。游戏中角色没有直接攻击能力，不安排角色徒手攻击基地。
- 第三天起，基地至少二级、已有三级火箭、没有上一日掉血警报时，可以用富余资金购买大型机器人召唤令。按实际价格购买后至少保留150金币；这只是固定的保守门槛，不代表已证明最优。
- 已携带的召唤令可在防线安全时使用，程序每天最多发出10次使用指令，失败也按一次占用本地额度，避免超限。防守攻击优先于召唤令。
- 不默认执行未经验证的“拆敌方围墙”。

## 地图配置与未确认规则

**仓库没有判题器和完整运行环境说明，因此本版还不是已验证胜率的比赛成品。**

任务书的建造区域示意图是外链图片，请求中也没有明确的可建造区域字段。默认参照 Demo 的几何假设：基地外第一圈建炮、第二圈建墙，再按中央来敌方向安排前侧半围墙。默认只修关键几段，并不保证机器人不会绕行或隔着围墙攻击。是否与真实裁判区域完全一致仍需核实。非法位置收到失败反馈后暂时避开130回合，并尝试其他位置。

可用 `tower_offsets` 和 `wall_offsets` 指定精确可用格子：每个 `[dx,dy]` 都相对于**己方基地左上角坐标**，y轴朝上。显式偏移不自动旋转，`tower_offsets` 前三个位置对应 `tower_loadout` 的顺序；墙按列表顺序建造并受 `wall_limit` 限制。空列表使用自动镜像的默认布局；不同阵营自定义布局不同时，应分别指定配置。

尚待官方环境验证：

1. 两炮和少量围墙能否守住真实波次，机器人寻路是否使默认围墙有效。
2. 火箭能否伤害敌方基地/角色；2×2基地是否按单位去重受伤。
3. 任务实际超时时间、奖励规模、刷新数量及是否具有可复用题型。
4. LLM真实返回格式、沙盒Python命令名、响应时序及冷却具体结算。

`attackRange`、`cooldown`、矿价等优先使用实际请求字段。回合编号按Demo采用1起算。未知矿山停工导致采集失败时，该矿点会暂时避开。本版不使用负数量交易、重复角色键、超额攻击目标或越权执行等未定义输入。

## 本地验证

在包含 `tests/` 和 `docs/` 的完整仓库中运行：

```bash
python -m unittest discover -s tests -v
```

测试覆盖：原仓库请求解析与HTTP接入、共享预算、路径和目标占用、夜间返程与冷却、伤害条件下的防守优先、试射反馈、任务跨回合回答、成功后缓存、缓存重新求解、命令超时、调用预算、半场状态重置，以及大量机器人下的响应耗时。

v2增加墙后工作接续、返程路线封堵、缺少石矿、商店不可达、半围墙镜像、火箭共用炮手交替发射、冷却期附近采矿、任务预算耗尽退出、失败采集切换目标，以及富余资金进攻和侦察条件的回归检查。

首日小型规则测试只实现基本移动、采集、交易和建造，用来检查两炮开局是否出现资金透支及返程失败；它没有完整战斗、随机刷新、敌方策略，也不是官方判题器。测试通过不代表生存10天或能够获胜。

代码入口：`zk_agent/__main__.py`；固定策略：`zk_agent/strategy.py`；任务处理：`zk_agent/tasks.py`；地图和行动约束：`zk_agent/world.py`。
